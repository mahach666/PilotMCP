# PilotMCP

MCP-сервер для работы с Pilot через Server API. Позволяет LLM-агентам подключаться к серверу Pilot, выполнять поиск, создавать и изменять объекты, работать с документами, историей изменений, правами доступа и чатами.

## Требования

- .NET 8.0
- Доступ к серверу Pilot


## Подключение к MCP-клиенту

Параметры подключения задаются через переменные окружения в конфигурации MCP-клиента:


| Переменная           | Описание                                                                   | Обязательная |
| -------------------- | -------------------------------------------------------------------------- | ------------ |
| `PILOT_SERVER_URL`   | URL сервера, например `http://localhost:5545/u_db_name`                    | да           |
| `PILOT_LOGIN`        | Логин пользователя                                                         | да           |
| `PILOT_PASSWORD`     | Пароль пользователя                                                        | да           |
| `PILOT_DATABASE`     | Имя базы данных (если пусто — берётся из URL)                              | нет          |
| `PILOT_LICENSE_TYPE` | Код лицензии: по умолчанию `100`                                           | нет          |
| `PILOT_READONLY`     | Режим только чтения: `true` или `1`. Блокирует все операции записи.        | нет          |
| `PILOT_ADMIN_LOGIN`  | Логин администратора сервера — для инструментов редактирования метаданных (автоматизации, типы, состояния). Если не задан, используется `PILOT_LOGIN`. | нет |
| `PILOT_ADMIN_PASSWORD` | Пароль администратора сервера                                            | нет          |



### Пример конфигурации (LM Studio, Ollama, Claude Code, Cursor и т.д.)

```json
{
  "mcpServers": {
    "pilot": {
      "command": "C:\\path\\to\\PilotMCP.exe",
      "env": {
        "PILOT_SERVER_URL": "http://localhost:5545/u_db_name",
        "PILOT_LOGIN": "username",
        "PILOT_PASSWORD": "password",
        "PILOT_DATABASE": "",
        "PILOT_LICENSE_TYPE": "103",
        "PILOT_READONLY": "false"
      }
    }
  }
}
```

### Режим только чтения

При `PILOT_READONLY=true` сервер сообщает модели об ограничениях через системный промпт при инициализации. Модель не будет пытаться выполнять операции записи и сразу сообщит пользователю об ограничении.

Заблокированы: `CreateObject`, `SetAttribute`, `DeleteObject`, `RestoreObject`, `MoveObject`, `LockObject`, `UnlockObject`, `FreezeObject`, `UnfreezeObject`, `MakeSecret`, `MakePublic`, `DeleteFile`, `SetUserState`, `Subscribe`, `Unsubscribe`, `AnnotateText`, `CreateAnnotation`, `SendMessage`, `EditMessage`, `ReplyMessage`, `CreateChat`, `UploadFile`, `InvokeCommand`, `CreateLink`, `DeleteRelation`, `AddAccessRecord`, `RemoveAllAccessRecords`, `UpdatePerson`, `ChangeSettings`, `CreateReport`, `UpdateReport`, `CreateTask`, `CreateWorkflow`, `AddSignatureRequest`, `CreateAutomationConfig`, `UpdateAutomationConfig`, `DeleteAutomationConfig`, `CreateType`, `UpdateType`, `DeleteType`, `AddTypeChildren`, `AddTypeAttribute`, `UpdateTypeAttribute`, `DeleteTypeAttribute`, `CreateUserState`, `UpdateUserState`, `DeleteUserState`, `CreateStateMachine`, `UpdateStateMachine`, `DeleteStateMachine`, `CreatePerson`, `UpdatePersonAdmin`, `DeletePerson`, `CreateOrgUnit`, `UpdateOrgUnit`, `DeleteOrgUnit`, `MoveOrgUnits`, `SetPersonOnPosition`, `RemovePersonFromPosition`.

## Архитектура

Bulk-инструменты (поиск, дочерние объекты и т.п.) записывают результаты во временные JSONL-файлы, а не возвращают данные напрямую в контекст. Это позволяет работать с тысячами объектов без перегрузки контекста модели.

```
Search("проект") → {resultFile: "tmp/search_x.jsonl", count: 8543}
     ↓
FilterObjects("tmp/search_x.jsonl", "typeName", "document") → tmp/filter_x.jsonl (85 записей)
     ↓
ExportCsv("tmp/filter_x.jsonl", "C:/result/docs.csv", "name,typeName,created")
```

Формат промежуточных файлов — JSONL (JSON Lines): один JSON-объект на строку.

#### Управление пользователями и оргструктурой (админский API)

Инструменты, помеченные `*`, требуют учётную запись **администратора сервера**
(`PILOT_ADMIN_LOGIN` / `PILOT_ADMIN_PASSWORD`) — см. раздел «Редактирование метаданных» ниже.
Блокируются режимом `PILOT_READONLY`.

| Инструмент                 | Описание                                                             |
| -------------------------- | -------------------------------------------------------------------- |
| `CreatePerson`             | Создать пользователя (логин, имя, пароль, признак администратора) *  |
| `UpdatePersonAdmin`        | Изменить логин, имя, пароль, isAdmin, активность *                   |
| `DeletePerson`             | Пометить пользователя удалённым *                                    |
| `CreateOrgUnit`            | Создать оргединицу: Department / Position / Group *                  |
| `UpdateOrgUnit`            | Изменить название оргединицы, признак руководителя *                 |
| `DeleteOrgUnit`            | Пометить оргединицу удалённой (если нет живых дочерних) *            |
| `MoveOrgUnits`             | Перенести оргединицы к новому родителю *                             |
| `SetPersonOnPosition`      | Назначить пользователя на должность *                                |
| `RemovePersonFromPosition` | Освободить должность *                                               |

Особенности сервера, выявленные тестами: новый пользователь **не сможет войти**, пока не назначен
на должность (`SetPersonOnPosition`); должности не могут находиться в корне оргструктуры —
только внутри отдела.

### Редактирование метаданных (типы, атрибуты, состояния)

Инструменты, помеченные `*`, работают через админский API сервера (как Pilot-myAdmin):
требуется учётная запись **администратора сервера** (`PILOT_ADMIN_LOGIN` / `PILOT_ADMIN_PASSWORD`;
если не заданы — используются основные логин/пароль). Каждая операция читает свежие метаданные,
вносит точечное изменение и записывает их обратно целиком, поэтому параллельные правки в myAdmin
не затираются. Все операции блокируются в режиме `PILOT_READONLY`.

| Инструмент            | Описание                                                                  |
| --------------------- | ------------------------------------------------------------------------- |
| `CreateType`          | Создать тип объекта (вид, файлы, монтируемость, родительские типы) *      |
| `UpdateType`          | Изменить тип (название, файлы, сортировка, машина состояний) *            |
| `DeleteType`          | Пометить пользовательский тип удалённым (IsDeleted) и убрать его из `Children` родителей * |
| `AddTypeChildren`     | Добавить дочерние типы (какие типы можно создавать внутри) *              |
| `AddTypeAttribute`    | Добавить атрибут к типу (Integer, String, DateTime, OrgUnit, ...) *       |
| `UpdateTypeAttribute` | Изменить атрибут типа *                                                   |
| `DeleteTypeAttribute` | Удалить атрибут типа *                                                    |
| `CreateUserState`     | Создать пользовательское состояние (цвет, признак завершения) *           |
| `UpdateUserState`     | Изменить пользовательское состояние *                                     |
| `DeleteUserState`     | Пометить состояние удалённым (если не используется в машинах) *           |
| `CreateStateMachine`  | Создать машину состояний с переходами (JSON) *                            |
| `UpdateStateMachine`  | Изменить машину состояний (название, полная замена переходов) *           |
| `DeleteStateMachine`  | Удалить машину состояний (если не привязана к типам) *                    |

### Сборка релиза

```bash
dotnet build -c Release
```

Релизная сборка дополнительно кладёт в `artifacts/` два готовых архива под `win-x64`:

| Архив                                        | Размер | Требования на машине пользователя |
| -------------------------------------------- | ------ | --------------------------------- |
| `PilotMCP-v<версия>-win-x64-selfcontained.zip` | ~75 МБ | ничего, .NET внутри               |
| `PilotMCP-v<версия>-win-x64.zip`               | ~43 МБ | установленный .NET 8 Runtime      |

В каждом архиве — `PilotMCP.exe` со всеми зависимостями, папка `ReportSamples`, `README.md` и `LICENSE.txt`. Отладочные символы (`.pdb`) исключены.

Версия берётся из `<Version>` в `PilotMCP.csproj`, платформа — из свойства `ReleaseRid` там же.

Собрать только архивы, без прочих проектов решения:

```bash
dotnet build PilotMCP.csproj -c Release
```

Отключить упаковку (например, в CI, где нужна только сборка):

```bash
dotnet build -c Release -p:SkipReleasePackaging=true
```
